# Coding Guardrails

1. Code changes MUST follow existing repository patterns when they exist.
2. New abstractions MUST solve observed complexity or match an established local pattern.
3. Changes MUST remain scoped to the requested task.
4. Public behavior MUST NOT change during refactors unless explicitly requested.
5. Generated or vendored files MUST NOT be hand-edited unless the repository documents that workflow.
6. Comments MUST explain non-obvious intent, constraints, or tradeoffs rather than restating code.
7. Formatting-only churn MUST be avoided unless formatting is the task or required by tooling.
