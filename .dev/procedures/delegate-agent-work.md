# Delegate Agent Work Procedure

## When To Use

Use when a task has bounded, separable workstreams that benefit from specialist investigation, implementation, review, or validation.

## Required Context

- User objective and current constraints.
- Workstream boundaries.
- Relevant files and knowledge.
- `.dev/delegation/protocol.yaml`.
- `.dev/delegation/roles.yaml`.

## Steps

1. Confirm delegation is allowed by protocol.
2. Assign a lead agent responsible for scope, integration, validation, and final response.
3. Define each delegated task with objective, scope, files, constraints, outputs, validation expectations, and stop conditions.
4. Share only necessary context.
5. Review delegate output before applying it.
6. Resolve conflicts and integrate changes.
7. Run final validation and report residual risk.

## Required Output

- Delegation plan.
- Delegate outputs or findings.
- Integration summary.
- Validation result and unresolved risks.

## Validation

- One lead agent remains accountable.
- Delegated scope is bounded.
- Delegate claims are evidence-backed or marked as assumptions.
- Integrated output is validated.
